# Larik SQL Studio

## Register
product

## Platform
desktop

## Users
- **Primary:** Backend and fullstack developers who work with Microsoft SQL Server, SQLite, and other relational databases in their daily workflow.
- **Secondary:** Data professionals and analysts who need a fast, intuitive SQL editor without the overhead of enterprise IDEs.

## Purpose
Larik SQL Studio redefines how developers interact with their databases — offering a SQL editor that is as fast, intuitive, and workspace-centric as Arc reinvented the browser. It replaces the clutter and cognitive load of traditional database IDEs with a focused, modern experience built around spaces, tabs, and seamless connection management.

## Success
A developer opens Larik by instinct — not because they have to, but because it makes working with SQL feel effortless. Success is a tool that stays out of the way, connects in seconds, and lets the user focus entirely on their queries and data.

## Positioning
Like DBeaver, but faster and more intuitive — bringing the Arc browser philosophy of workspaces and chrome-minimal design to SQL development.

## Brand Personality
Swift, Intuitive, Distinctive

## Anti-References
- **SSMS:** Cluttered, outdated, overwhelming tooling. Larik must never feel like a legacy enterprise IDE.
- **Generic AI Slop:** Overused design patterns — Inter font everywhere, purple-to-blue gradients, nested cards, gray text on colored backgrounds, rounded-square icon trays above every heading. Larik must have its own visual identity.

## Strategic Principles
1. **Speed is a feature.** Every interaction should feel instant — connect, query, switch spaces, navigate tabs.
2. **Spaces over windows.** The Arc-inspired workspace model lets developers organize by context, not by file.
3. **Safety through visibility.** Connection status, database context, and active query state must always be glanceable. A developer should never accidentally query production.
4. **Chrome recedes, code advances.** The UI gets out of the way. Sidebar, toolbars, and chrome exist to serve the editor, not compete with it.
5. **Opinionated defaults, flexible paths.** Sensible defaults for fonts, spacing, and layout — but each space can have its own identity through color and connection config.

## Accessibility & Inclusion
- WCAG AA contrast minimum (4.5:1 body text, 3:1 large text) across all themes.
- Support prefers-reduced-motion: animations degrade gracefully to crossfades or instant transitions.
- Dark and light themes with proper contrast in both.
- Connection status must be both color-coded AND text-labeled (never color-only).
